# Worker节点管理页 - 页面设计规范

> 页面路径: `/infrastructure/worker`
> 所属模块: 基础设施管理模块
> 覆盖 MASTER 规范: 资源监控表格，状态实时更新

## 页面目标

管理数据中台的 Worker 执行节点，包括 SSH 连接配置、执行环境配置、节点状态监控和节点分组管理，为数据迁移、数据治理等任务提供执行节点资源池。

### 认证方式

| 方式      | 说明                         |
| --------- | ---------------------------- |
| 密钥认证  | 推荐，使用SSH密钥文件认证    |
| 密码认证  | 使用用户名密码认证（不推荐） |
| 密钥+密码 | 密钥认证 + 密钥密码          |

### SSH密钥管理

系统统一管理SSH密钥：

- 密钥存储在安全的密钥管理系统
- 密钥文件路径格式: `/etc/ssh/keys/{key-name}.pem`
- 支持密钥版本管理和轮换
- 密钥权限审计记录

### 权限校验项

连接测试时校验以下权限：

- SSH连接是否成功
- 认证是否通过
- 是否有执行命令权限
- 是否有读写指定目录权限
- 是否有启动服务权限

- 检测各引擎安装路径是否存在

### 状态异常告警

| 异常类型    | 告警级别 | 告警方式            |

| CPU > 90%   | Warning  | Toast 提示          |

| 网络断开    | Critical | 立即通知 + 节点离线 |
| SSH会话断开 | Warning  | Toast 提示          |

## Worker与任务的关联

### 任务执行节点选择

任务创建时通过**Worker引用**指定执行节点：

```
{
  "taskId": "migration-001",
  "worker": {
    "ref": "worker-group-a",           // 引用Worker分组
    "strategy": "leastLoad",           // 选择策略
    "fallback": "worker-group-backup"  // 失败回退分组
  }
}
```

### Worker选择策略

| 策略     | 说明                         |
| -------- | ---------------------------- |
| 固定节点 | 指定固定Worker节点执行       |
| 负载均衡 | 自动选择负载最低的节点       |
| 随机选择 | 随机选择可用节点             |
| 标签匹配 | 根据任务标签匹配合适的Worker |

### 任务执行流程

```
任务创建 → Worker分组选择 → 负载检查 → 选择节点 → SSH连接 → 执行任务
                                  ↓
                            资源不足 → 排队等待 → 执行
                                  ↓
                            节点故障 → 故障转移 → 备用节点执行
```

## 技术实现要点

- **SSH连接**: 使用 SSH2 库建立连接
- **命令执行**: 远程执行命令并获取输出
- **状态监控**: Agent 定期上报状态（心跳）
- **日志采集**: Filebeat 收集日志到 Elasticsearch
- **负载均衡**: 根据Worker资源使用情况分配任务
- **故障转移**: Worker故障时自动切换到备用节点
