# 阶段 1：SDK 模块划分（一级索引）

本阶段仅定义平台的 **一级索引层**：基于 DDD 限界上下文将平台拆分为独立、解耦、可插拔的 SDK 模块。  
**禁止**在本阶段出现：功能点清单、共享实体字段、接口入参出参、错误码、Mock 等后续阶段内容。

## 模块划分总览（16 个）

> 领域定位用于支撑渐构式交付：基础核心 → 业务能力 → 治理安全

### A. 基础核心（6）

#### 1) `data-integration`（数据接入集成）

- **限界上下文边界**：
  - 负责数据从各类数据源进入数据中台的“接入与加工”全流程：数据源接入配置、接入策略、数据探查、标准化执行、自助 SQL 开发执行等。
  - 仅负责“接入过程的初始元数据采集”，不承担元数据全生命周期管理。
- **核心领域定位**：基础核心

#### 2) `data-service`（通用数据 API 服务）

- **限界上下文边界**：
  - 负责把中台数据能力以“技术层”API 的形式对外暴露：服务发布/下线、授权、流量与频控、调用日志与统计监控。
  - 不承载跨机构共享交换的“业务审批/事项/门户流程”（归属 `data-sharing`）。
- **核心领域定位**：基础核心

#### 3) `metadata`（元数据全生命周期）

- **限界上下文边界**：
  - 负责元数据全生命周期管理：自动/订阅/手动采集、导入导出、同步、版本管理、变更订阅等。
  - 元数据能力覆盖并统一纳管：ETL 任务、数据模型、数据服务等的元信息版本与变更。
  - 不负责数据接入侧的接入编排与数据清洗加工（归属 `data-integration`）。
- **核心领域定位**：基础核心

#### 4) `data-organization`（数据分层组织）

- **限界上下文边界**：
  - 负责数据在中台内部“分层与组织”规则的管理与入层组织：业务库/原始库/资源库/主题库的数据资源组织与入库映射。
  - 不负责治理标准制定（归属 `data-governance-core`），不负责接入侧的清洗标准化执行（归属 `data-integration`）。
- **核心领域定位**：基础核心

#### 5) `task-scheduler`（统一任务调度中心）

- **限界上下文边界**：
  - 负责统一调度：DAG 编排、触发策略、队列与优先级、资源隔离、集群负载均衡、统一日志。
  - 各业务模块可保留自身“任务定义/配置”，但调度执行归口本模块。
- **核心领域定位**：基础核心

#### 6) `system-auth`（身份认证与审批框架）

- **限界上下文边界**：
  - 负责统一身份与访问控制：组织、用户、角色、应用/菜单权限、数据权限基础框架。
  - 提供统一审批流程框架：审批模板、待办/已办、流程跟踪、提醒等。
  - 不承载系统工具类杂项（归属 `system-admin`）。
- **核心领域定位**：基础核心

---

### B. 业务能力（6）

#### 7) `data-operations`（数据运维监控）

- **限界上下文边界**：
  - 负责运行态的可观测与运维：任务运维监控、告警策略、多渠道通知、对账、运维报表、数据源/ETL/同步监控等。
  - 不负责调度编排（归属 `task-scheduler`），不负责权限/审批框架（归属 `system-auth`）。
- **核心领域定位**：业务能力

#### 8) `cost-management`（成本管理）

- **限界上下文边界**：
  - 负责存储与计算成本的统计与配额策略：按项目/组织维度统计、配额、超限告警、优化建议。
  - 不负责生命周期分层策略本身（归属 `data-lifecycle`）。
- **核心领域定位**：业务能力

#### 9) `data-sharing`（数据共享交换门户）

- **限界上下文边界**：
  - 负责跨机构/跨单位的数据共享交换“业务域”：事项任务、资源登记/编制、服务申请、审批、调度监控、门户使用等完整业务流程。
  - 依赖 `data-service` 提供“技术层”服务发布与调用能力，但审批与门户流程属于本模块业务边界。
- **核心领域定位**：业务能力

#### 10) `self-service-analytics`（用户自助数据分析）

- **限界上下文边界**：
  - 负责面向业务用户的自助分析体验：即席查询、可视化、导出、保存分享、数据探索。
  - 不负责底层 SQL 执行引擎与开发任务运行（归属 `data-integration`），不负责数据服务发布（归属 `data-service`）。
- **核心领域定位**：业务能力

#### 11) `system-admin`（系统工具管理）

- **限界上下文边界**：
  - 负责系统工具与运营管理类能力：函数管理、项目管理、驱动管理、操作日志、我的工单等。
  - 不负责认证授权与审批框架（归属 `system-auth`）。
- **核心领域定位**：业务能力

#### 12) `system-integration`（外部系统集成）

- **限界上下文边界**：
  - 负责对接外部能力：统一身份认证（OAuth2/LDAP/AD）、消息通知渠道、消息中间件、文件存储等集成适配。
  - 不在本模块内实现业务规则，只提供标准适配与连接器能力。
- **核心领域定位**：业务能力

---

### C. 治理安全（4）

#### 13) `data-governance-core`（数据治理核心基础设施）

- **限界上下文边界**：
  - 负责治理核心基础设施：数据地图（资产视图）、数据资产搜索/标签（资产层面）、数据标准（数据元/字典）、数据模型管理等。
  - 不承载治理运行操作（质量/血缘/标签提取任务等，归属 `data-governance-ops`）。
- **核心领域定位**：治理安全

#### 14) `data-governance-ops`（数据治理运行操作）

- **限界上下文边界**：
  - 负责治理运行与闭环操作：数据质量管理（规则/任务/报告/工单）、标签管理（规则/任务/查询）、血缘分析（采集/展示/影响分析）等。
  - 不负责标准定义与模型基础设施（归属 `data-governance-core`）。
- **核心领域定位**：治理安全

#### 15) `data-security`（数据安全）

- **限界上下文边界**：
  - 负责数据安全防护：脱敏、分级分类、行级权限控制、水印、加密等安全能力。
  - 不负责审批框架（归属 `system-auth`），但可复用其权限与审批基础能力。
- **核心领域定位**：治理安全

#### 16) `data-lifecycle`（数据生命周期管理）

- **限界上下文边界**：
  - 负责数据生命周期策略与执行：冷热温分层策略、归档、恢复、过期删除、统计报表。
  - 不负责成本统计与配额（归属 `cost-management`）。
- **核心领域定位**：治理安全
