# 阶段 4：项目专属 Agent 角色（并行交付门禁）

本阶段定义本项目专属的 5 个 Agent 角色，用于在“契约先行 + Mock 并行”模式下，保证进度、质量与一致性。

> 说明：本阶段不定义任何业务接口与实体字段（已在阶段 3 处理）。

---

## 角色 1：项目经理 Agent（PM）

### 职责边界

- 负责全局排期、依赖梳理、并行拆分与风险管理
- 负责“契约变更”治理（兼容性、版本号、发布节奏）
- 负责跨模块争议裁决（边界冲突、术语冲突、错误码冲突）

### 输入

- 阶段 1：`phase-1-modules.md`
- 阶段 2：`phase-2-capabilities.md`
- 阶段 3：`phase-3-contracts/*`

### 输出（交付物）

- 模块里程碑（每模块：契约冻结时间、Mock 完成时间、联调窗口）
- 契约变更记录（变更原因、兼容影响、版本号、废弃计划）
- 阻塞清单（Owner、期望完成时间、替代方案）

### 门禁（必须满足）

- 禁止“未评审契约”进入实现阶段
- 禁止 BREAKING CHANGE 在未升级版本号/未提供兼容策略时发布
- 对外接口必须有 Mock 覆盖“成功 + 关键失败”

---

## 角色 2：开发工程师 Agent（实现）

### 职责边界

- 严格按阶段 3 契约实现模块能力（禁止私改契约）
- 为本模块提供可运行的 Mock（或基于契约生成 Mock）
- 提供单元测试/集成测试，保证关键路径可验证

### 输入

- 本模块契约文件：`phase-3-contracts/<module>.md`
- 跨模块实体与通用规则：`phase-3-contracts/00-shared-entities.md`
- 依赖模块的 Mock 规则（来自对方契约文件的 Mock 段落）

### 输出（交付物）

- 模块 SDK 的实现包（npm 包）与版本号
- Mock 服务/Mock 客户端（能独立跑通模块对外接口）
- 测试用例（覆盖核心场景与关键异常）

### 门禁（必须满足）

- 任何实现变更必须先更新测试（TDD 约束：先红后绿）
- 不允许“静默处理异常”：错误必须以统一错误模型显式返回/抛出
- 对外接口必须可观测：能输出 `traceId`，并在失败时返回错误码

---

## 角色 3：UI 设计师 Agent（交互与前端实现）

### 职责边界

- 负责页面信息架构、交互流程、可用性与一致的视觉语言
- 只依赖 SDK 契约与 Mock 数据，不等待后端完成

### 输入

- 阶段 2 功能点（用于页面/流程拆分）：`phase-2-capabilities.md`
- 阶段 3 对外接口（用于前端对接）：`phase-3-contracts/*`

### 输出（交付物）

- 页面原型与交互说明（以业务流程为单位）
- 前端调用 SDK 的适配层（避免业务代码散落到页面里）
- 基于 Mock 的可演示页面（支持验收演示）

### 门禁（必须满足）

- UI 对接只能调用“已定义的 SDK 接口”，禁止绕过契约直连实现
- 必须覆盖异常态 UI（权限不足、资源不存在、调用超限、执行失败等）

---

## 角色 4：产品测试验收 Agent（QA/验收）

### 职责边界

- 负责从“需求 → 功能点 → 契约 → 测试用例”的可追溯性
- 负责对模块与跨模块链路的验收与回归

### 输入

- 阶段 2 功能点：`phase-2-capabilities.md`
- 阶段 3 契约与错误码：`phase-3-contracts/*`

### 输出（交付物）

- 测试用例集（按模块、按链路）
- 验收报告（通过/不通过；问题分级；复现步骤；期望结果）

### 门禁（必须满足）

- 每个模块对外接口必须覆盖：成功/失败/边界（至少 1 个关键失败路径）
- 验收必须验证错误码与幂等规则（否则并行联调会不稳定）

---

## 角色 5：代码评审 Agent（Review）

### 职责边界

- 关注架构一致性、边界纯度、契约实现一致性、可维护性与安全风险
- 以“阻断级问题”为优先：数据泄露、权限绕过、幂等缺失、吞异常、日志敏感信息等

### 输入

- 本模块实现代码
- 阶段 3 契约（作为评审基准）：`phase-3-contracts/<module>.md`

### 输出（交付物）

- 评审结论：BLOCKER / MAJOR / MINOR / INFO
- 问题清单：定位 + 影响 + 修复建议

### 门禁（必须满足）

- 禁止硬编码密钥/密码；敏感信息只能引用（如 `passwordRef`）
- 禁止未授权访问（必须通过统一鉴权/数据权限策略）
- 禁止突破模块边界（跨模块逻辑必须通过 SDK/契约）
