# 附录：渐构式建设路径（基础核心→业务能力→治理安全）

> 本附录在阶段 1-4 均完成后生成，用于把 16 个模块映射到增量上线阶段，并定义每阶段 MVP 交付。

## 1. 阶段划分原则（MVP）

- **先打通端到端最短链路**：数据进入 → 被治理/可发现 → 可服务化对外使用
- **先平台底座，再业务体验，再治理安全增强**
- **每阶段可独立验收**：能演示、可回归、可度量

---

## 2. 阶段一：基础核心（MVP 核心底座）

### 2.1 包含模块

- `data-integration`
- `metadata`
- `data-organization`
- `task-scheduler`
- `system-auth`
- `data-service`

### 2.2 MVP 交付清单（验收口径）

- 能完成数据源接入与接入任务提交（含初始元数据采集）
- 能完成基础的元数据采集/同步/导入导出（形成可检索元数据资产）
- 能完成数据分层组织的最小能力（至少能把标准/资源/主题任一层跑通）
- 统一调度中心可运行（至少支持手动触发与定时触发）
- 认证与权限可用（至少用户/角色/菜单权限；审批框架具备最小闭环）
- 数据服务可发布与调用（至少查询类服务 + 授权校验 + 调用日志）

---

## 3. 阶段二：业务能力（可用性与业务流程）

### 3.1 包含模块

- `data-operations`
- `data-sharing`
- `self-service-analytics`
- `system-admin`
- `system-integration`
- `cost-management`

### 3.2 MVP 交付清单（验收口径）

- 运维监控可用：任务监控、告警策略、多渠道通知、基本报表
- 共享交换门户可用：资源登记/编制、服务申请、审批、使用、调度监控（最小闭环）
- 自助分析可用：保存查询、执行、导出、基础可视化
- 系统工具可用：项目管理、函数管理、操作日志、工单
- 外部集成可接入：至少完成 1 个身份源 + 1 个通知渠道 + 1 个文件存储适配
- 成本管理可用：至少存储成本统计 + 配额策略 + 优化建议雏形

---

## 4. 阶段三：治理安全（企业级治理与安全闭环）

### 4.1 包含模块

- `data-governance-core`
- `data-governance-ops`
- `data-security`
- `data-lifecycle`

### 4.2 MVP 交付清单（验收口径）

- 数据地图与资产搜索可用（含资产标签）
- 数据质量闭环可用（规则→任务→报告→工单）
- 标签运行可用（规则/任务/查询；支持交集/并集碰撞）
- 血缘采集与影响分析可用（至少覆盖 ETL/SQL/服务三者中的两类）
- 数据安全可用：脱敏、分级分类、行级权限（最小可用闭环）
- 生命周期策略可用：归档/恢复/删除（至少 dryRun + 报表）
