# AIDataHub 设计系统优化计划

> 分析日期: 2026-04-03

> 分析目标: 评估设计合理性，提出优化建议

## 一、设计系统总体评估

### 1.1 整体架构评价

| 维度       | 评分       | 说明                                                 |
| ---------- | ---------- | ---------------------------------------------------- |
| 文档完整性 | ⭐⭐⭐⭐⭐ | 77个设计文件覆盖11个模块、32个菜单页面，文档层级清晰 |
| 规范一致性 | ⭐⭐⭐⭐   | MASTER.md 定义清晰，但部分页面存在规范覆盖不一致     |
| 导航设计   | ⭐⭐⭐⭐   | 层级结构合理，但存在路由冲突和跨模块导航缺失         |
| 交互设计   | ⭐⭐⭐     | 核心交互定义完善，但空状态、加载状态、错误处理缺失   |
| 可访问性   | ⭐⭐⭐     | MASTER.md 定义了规范，但页面级实现细节不足           |
| 响应式设计 | ⭐⭐⭐     | 定义了断点，但复杂页面（血缘、DAG）移动端适配未说明  |

**总体评分**: 4.0/5.0 — 设计文档体系成熟，但存在若干需要优化的问题。

### 1.2 设计亮点

1. **MASTER + Overrides 模式** — 全局规范与页面覆盖分离，便于维护
2. **四级配置继承架构** — 系统→租户→项目→任务，复用性强
3. **页面类型标识系统** — `[M]`/`[D]`/`[C]`/`[T]` 分类清晰
4. **模块索引文档** — 每个模块有 index.md 说明概览和页面类型
5. **权限控制矩阵** — 每个页面定义角色权限，便于前端实现
6. **图表选型指南** — MASTER.md 提供数据类型→图表映射
7. **基础设施关联设计** — 各模块明确引用基础设施配置资源

## 二、关键问题分析

### 2.1 导航结构问题

#### 问题 P1: 首页路由定义冲突

| 文件                     | 定义                                                        | 问题               |
| ------------------------ | ----------------------------------------------------------- | ------------------ |
| navigation.md (L47-55)   | `/` → 首页仪表盘，文档 `sharing/home-dashboard.md`          | 与数据共享首页冲突 |
| navigation.md (L216-222) | `/sharing` → 数据共享首页，文档 `sharing/home-dashboard.md` | 同一文档，不同路由 |

**影响**: 用户访问 `/` 和 `/sharing` 显示相同内容，造成困惑。

**建议**:

- `/` 应为系统全局首页（展示跨模块关键指标）
- `/sharing` 为数据共享模块首页（展示共享模块特定内容）
- 需新建 `common/dashboard.md` 定义系统首页设计

#### 问题 P2: 导航层级不一致

| 模块       | 菜单层级              | 问题                       |
| ---------- | --------------------- | -------------------------- |
| 元数据管理 | 一级菜单，仅1个子页面 | 单页面模块不应作为一级菜单 |
| 数据组织   | 一级菜单，仅2个子页面 | 可合并到数据治理或数据集成 |
| 任务队列   | 一级菜单，仅1个子页面 | 可合并到系统管理           |

**建议**: 精简一级菜单，将单页面模块归入相关父模块。

#### 问题 P3: 跨模块导航路径缺失

| 场景                    | 当前状态   | 需要补充                         |
| ----------------------- | ---------- | -------------------------------- |
| 数据源列表 → 数据探查   | 无直接导航 | 需从数据源卡片添加「探查」入口   |
| 数据质量 → 数据治理任务 | 无关联     | 需从质量检测结果跳转治理任务详情 |
| 服务目录 → 数据血缘     | 无关联     | 服务详情应展示数据血缘入口       |

**建议**: 在页面设计中补充跨模块跳转入口定义。

### 2.2 页面设计规范问题

#### 问题 P4: 响应式设计缺失

以下页面定义了「全屏画布」设计，但未说明移动端适配：

| 页面         | 文档             | 问题描述                         |
| ------------ | ---------------- | -------------------------------- |
| 数据血缘分析 | lineage.md       | 全屏图形展示，移动端如何操作？   |
| DAG编排      | scheduler/dag.md | 拖拽连线操作，移动端无 hover     |
| SQL开发      | sql-dev.md       | 代码编辑器，移动端键盘交互未说明 |

**建议**: 为复杂交互页面补充移动端适配方案：

- 血缘/DAG：移动端提供简化视图 + 文字列表模式
- SQL开发：移动端仅支持查看，编辑需跳转桌面提示

#### 问题 P5: 卡片组件规范不一致

| 页面       | 卡片宽度 | 卡片内容                     | 问题                 |
| ---------- | -------- | ---------------------------- | -------------------- |
| 数据源列表 | 未定义   | 图标+名称+描述+状态+操作     | 缺少尺寸规范         |
| 服务目录   | 未定义   | 类型标签+名称+描述+统计+操作 | 与数据源卡片结构不同 |
| 项目列表   | 320px    | 名称+编号+阶段+进度+负责人   | 有明确尺寸           |

**建议**: 在 MASTER.md 补充通用卡片组件规范：

```markdown
## Card Component

- Width: 280px (桌面) / 100% (移动端)
- Padding: 16px
- Structure: 图标(左上) + 标题 + 描述(2行截断) + 元信息 + 操作区
```

#### 问题 P6: 表格列宽定义分散

不同页面的表格列宽定义风格不一：

| 页面         | 定义方式           | 问题    |
| ------------ | ------------------ | ------- |
| 迁移任务列表 | 具体像素值 (200px) | ✓ 精确  |
| 租户管理     | 具体像素值 (180px) | ✓ 精确  |
| 项目列表表格 | 具体像素值 (120px) | ✓ 精确  |
| 质量规则定义 | 无列宽定义         | ❌ 缺失 |

**建议**: 在 MASTER.md 定义表格列宽标准：

```markdown
## Table Column Width

- 标识列(ID/编号): 100-120px
- 名称列: 180-200px
- 描述列: 自适应 (min 200px)
- 状态列: 80-100px
- 操作列: 120-150px
```

### 2.3 交互设计缺失

#### 问题 P7: 空状态设计缺失

所有列表页均未定义空状态：

| 页面         | 需要空状态场景 | 当前状态 |
| ------------ | -------------- | -------- |
| 数据源列表   | 无数据源时     | 未定义   |
| 迁移任务列表 | 无任务时       | 未定义   |
| 服务目录     | 无服务时       | 未定义   |
| 审批待办     | 无待办时       | 未定义   |

**建议**: 在 MASTER.md 添加空状态规范：

```markdown
## Empty State

- 图标: 64px，灰色 (#94A3B8)
- 标题: Body (16px)，"暂无数据"
- 描述: Body Small (14px)，场景化文案
- 操作: 主按钮，引导用户创建
```

#### 问题 P8: 加载状态设计缺失

以下页面需要数据加载但未定义加载状态：

| 页面     | 加载场景 | 需要定义            |
| -------- | -------- | ------------------- |
| 数据血缘 | 图形渲染 | Skeleton 或 Spinner |
| DAG编排  | DAG加载  | Skeleton 画布       |
| 数据探查 | 探查执行 | 进度条 + 预估时间   |
| 质量检测 | 规则执行 | 进度百分比          |

**建议**: 在 MASTER.md 添加加载状态规范：

```markdown
## Loading State

- 初始加载: Skeleton 占位，保持布局稳定
- 操作加载: Button Spinner + 禁用状态
- 长时任务: 进度条 + 预估时间 + 取消按钮
```

#### 问题 P9: 错误处理设计不完整

仅迁移任务列表定义了错误提示，其他页面缺失：

| 场景         | 当前定义   | 需补充             |
| ------------ | ---------- | ------------------ |
| 表单验证错误 | 部分页面有 | MASTER.md 统一规范 |
| API请求失败  | 未定义     | Toast + 重试机制   |
| 权限不足     | 部分页面有 | 统一提示 + 跳转    |
| 系统异常     | 未定义     | 错误页设计         |

**建议**: 在 MASTER.md 添加错误处理规范：

```markdown
## Error Handling

### 表单验证

- 错误标签: 红色文字，字段下方
- 聚焦: 自动聚焦第一个错误字段

### API错误

- Toast: 红色背景，显示错误消息
- 重试: 提供「重试」按钮

### 系统错误页

- 500: 错误图 + "系统异常" + 联系支持
- 404: 错误图 + "页面不存在" + 返回首页
- 403: 错误图 + "无访问权限" + 申请权限
```

### 2.4 表单设计缺失

#### 问题 P10: 复杂表单流程不完整

| 表单          | 当前定义      | 缺失项                 |
| ------------- | ------------- | ---------------------- |
| 新建租户(4步) | 步骤定义完整  | 无取消/保存草稿机制    |
| 新建迁移任务  | 快速/高级模式 | 无模式切换说明         |
| 质量规则配置  | 表单字段定义  | 无规则表达式编辑器规范 |
| DAG节点配置   | 属性面板定义  | 无配置预览/回退机制    |

**建议**: 在 MASTER.md 添加多步骤表单规范：

```markdown
## Multi-Step Form

- 进度指示器: 步骤名称 + 完成标记
- 导航: 上一步(次按钮) / 下一步(主按钮)
- 取消: 二次确认，提示未保存数据丢失
- 保存草稿: 自动保存或手动保存按钮
- 步骤验证: 每步完成前验证当前步骤
```

#### 问题 P11: 表单字段规范分散

| TextArea   | 分散定义 | 无行数/字数限制规范     |

**建议**: 在 MASTER.md 添加表单字段规范章节。

## 五、优化实施建议

### 5.1 文档修改顺序

建议按以下顺序修改设计文档：

```
1. MASTER.md (添加缺失的通用规范)
   ↓
2. navigation.md (修复路由冲突和菜单层级)
   ↓
3. common/dashboard.md (新建系统首页设计)
   ↓
4. 各模块页面文档 (补充空状态、加载状态、关联入口)
   ↓
5. 复杂交互页面 (血缘、DAG、SQL - 补充移动端和可访问性)
```

### 5.2 文档模板建议

建议创建以下文档模板，便于后续页面设计一致性：

#### 空状态模板

```markdown
## 空状态设计

| 场景       | 图标     | 主文案           | 副文案                     | 操作按钮   |
| ---------- | -------- | ---------------- | -------------------------- | ---------- |
| 无数据     | [图标名] | "暂无XX数据"     | "点击下方按钮创建第一个XX" | [新建XX]   |
| 无权限     | [图标名] | "无访问权限"     | "请联系管理员申请权限"     | [申请权限] |
| 搜索无结果 | [图标名] | "未找到匹配结果" | "请尝试其他搜索条件"       | [清空筛选] |
```

#### 加载状态模板

```markdown
## 加载状态设计

| 场景     | 加载方式       | 显示内容           | 用户操作   |
```

### 5.3 验收标准

优化完成后需满足以下标准：

## 七、总结

AIDataHub 设计系统文档体系整体成熟，采用了清晰的层级架构和规范分离模式。本次分析识别出 **13 个关键问题**，涵盖导航设计、规范一致性、交互完整性、可访问性四个维度。

**核心优化方向**:

1. **规范补全** — MASTER.md 需补充空状态、加载状态、错误处理、表单字段等通用规范
2. **导航修复** — 解决首页路由冲突，精简一级菜单层级
3. **页面完善** — 为复杂交互页面补充移动端适配、加载状态、跨模块关联
4. **可访问性** — 为图形化页面补充键盘操作和文字替代方案

**预估总工作量**: 19.5h，分三个 Phase 实施。

建议优先完成 Phase 1（核心规范完善），为后续前端开发提供统一的设计基础。
